# ADR: Scikit-learn Library for FracFeedExtractor
**Author:** Sean Clayton  
**Date:** 11-16-2025

## 1. Context
Our project requires a text classification pipeline that can label predator diet survey PDFs as useful or not useful for the predator diet dataset workflow. This requires:
- A reliable machine learning library supporting TF-IDF vectorization, supervised classification, and probability scoring. [2] [3]
- Easy integration with Python, which is already our team’s primary environment. [4]
- Good documentation, stability, and low risk of breaking changes.
- Enough model performance to support a growing dataset (~1220 PDFs as of November 2025).
- Lightweight dependencies so team members can run training locally and in CI environments.

## 2. Decision
We will use scikit-learn (sklearn) as the machine learning library for training and running the PDF usefulness classifier. Specifically:
- `TfidfVectorizer` for text feature extraction [3]
- `LogisticRegression` for binary classification [2]
- `predict()` + `predict_proba()` for classification and confidence scoring
- `joblib` for model and vectorizer persistence [1]

This decision governs all model training, evaluation, and prediction across the project.

## 3. Options Considered
**Option A — scikit-learn (Chosen)**  
Traditional ML library providing TF-IDF, linear models, and simple pipelines.

**Option B — HuggingFace Transformers**  
Use pretrained large language models (BERT, RoBERTa) that are fine tuned for classification.

**Option C — spaCy TextCat**  
Use spaCy’s built-in convolutional text classifier with token-level embeddings.

**Option D — Do Nothing (no ML classifier)**  
Rely on manual labeling, keyword heuristics, or static rules.

## 4. Rationale
**Why scikit-learn?**
- **Simplicity:** Training the model required <40 lines of code with no GPU or special setup.
- **Performance:** Initial accuracy was acceptable (>90%) using a balanced dataset of 620 useful and 600 not-useful PDFs.
- **Reproducibility:** Models are persisted easily via joblib and work consistently across environments. [1]
- **Security:** Smaller dependency surface than deep learning frameworks. No model download, no external inference API.

## 5. Consequences
- **Accuracy ceiling:** Future improvements may require moving to embeddings or a hybrid pipeline.
- **Model retraining overhead:** TF-IDF and Logistic Regression are stateless learners so any updates to labeled data will require a full retraining cycle rather than incremental updates.
- **Lower representational power:** TF-IDF + Logistic Regression cannot capture deep semantic meaning, making it less effective than transformer-based models on complex text.
- **Limited text understanding:** Some false positives/negatives may be due to lack of contextual semantics.
- **Pipeline rigidity:** The pipeline assumes clean text extraction so poor OCR or noisy PDF text can degrade performance significantly without built-in robustness.
